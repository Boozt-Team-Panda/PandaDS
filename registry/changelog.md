## Session 2 — 2026-02-27 · Design Sync: Spacing naming conventions and primitives

**Attendees:** Justin Daneman, Patrick Ahrentløv, Lasse Lind Dencker Sørensen, Daniel Wennberg, Rasmus Sander Larsen, Danas Paulikas *(Facundo absent)*

### Decisions ratified

| ID | Decision |
|----|----------|
| DS-006 | Semantic layer: four use cases — edge (container→first child), flow (vertical gap), inline (horizontal gap), gutter (page-level outer space) |
| DS-007 | No platform-specific values in primitive layer — handled via Figma modes at semantic/component layer |
| DS-008 | Size tokens (stroke, font, icon size) are a separate primitive category from spacing |
| DS-009 | Primitives kept minimal; new values require demonstrated use case and must be multiples of 4; values >80 need written justification |
| DS-010 | Layer responsibility clarified: semantic = brand differences, component = platform differences |
| DS-011 | Primitives must not be exposed in code — export script must be updated to surface semantic layer only |

### Open threads created
- **OT-005** Web/Philip to justify need for spacing above 80 (128 specifically)
- **OT-006** Justin + Danas: scaled-up page examples (PDP etc.) to validate primitive values

- **OT-009** Icons — still pending

### Notes
- "Boundary" officially renamed to "gutter"
- "Flow" name accepted for vertical spacing despite Android naming conflict (progress over perfection)
- Zero spacing not added to primitives; Android can hard-code `0dp` where needed as a special case
- Value 44 noted as potentially needed for iOS touch targets — deferred to sizes/component discussion
